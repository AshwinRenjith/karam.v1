# KaramLLM v2 — Upgrade Strategy & Phased Migration Plan

## Objective

Upgrade KaramLLM from prototype quality to production-grade capability without breaking:
- existing training workflows,
- registry lineage integrity,
- inference API contracts,
- Mac M1/M2 (MPS) stability.

This plan is designed to maximize quality gain while minimizing migration risk.

---

## Core Principles (Non-Negotiable)

1. **No blind rewrites**: every architectural change ships behind a migration gate.
2. **Contract-first evolution**: API + registry schema are versioned before model changes.
3. **Checkpoint safety**: architecture-breaking changes never load old weights implicitly.
4. **MPS-first reliability**: thermals/memory are treated as first-class constraints.
5. **Reproducibility**: each phase has success criteria, rollback conditions, and artifacts.

---

## Current Readiness Snapshot

### Strengths already present
- Fractal hierarchy and budding pipeline exist.
- Semantic routing, registry, and runtime serving are operational.
- Distillation pathway exists and can be extended.

### Current risk factors
- Architecture migration can invalidate legacy checkpoints.
- Registry/config drift can break model reconstruction at inference time.
- Padding-related loss contamination can reduce language quality.
- Router centroid persistence cold-start risk remains.

This means: **v2 is feasible now**, but only with staged migration.

---

## v2 Target Architecture (End State)

- **Backbone**: RMSNorm + RoPE + SwiGLU (Llama-style modernization).
- **Attention**: bias-free qkv/out, RoPE on Q/K only.
- **FFN**: SwiGLU with 3 matrices, diet-scaled intermediate width.
- **Scaling law update**: \(d_{ff}=\lceil \frac{8}{3} d_{child} \rceil_{256}\) (round up to 256 multiple).
- **Loss hygiene**: strict causal shift + `ignore_index=pad_id` everywhere (pretrain/distill/SFT).
- **Registry versioning**: store explicit architecture and full node config for reliable reconstruction.

---

## Mandatory Compatibility Rules (Before Any Code Merge)

1. **Registry schema v2** must store:
   - `arch_version`
   - `d_model`, `n_heads`, `n_layers`, `d_ff`, `vocab_size`, `max_seq_len`, `pad_token_id`
2. **Inference must never derive `d_ff` heuristically** (no `4*d_model` fallback for v2 nodes).
3. **Weight loading must be explicit in a hard-cutover model family**:
  - `main` branch keeps stable v1 until migration starts.
  - `v2-modernization` branch serves only `v2_rope_swiglu` checkpoints.
  - runtime must reject incompatible `arch_version` with a clear error.
4. **Tokenizer special tokens** for chat must trigger safe embedding/head resize.
5. **All CE losses** in training scripts must ignore padding index.

## The Final Phased Plan

## Phase 0 — Safety Rail Setup (1 day)

### Goal
Prepare zero-break migration infrastructure using branch-based hard cutover.

### Deliverables
- Create and lock migration branch: `v2-modernization`.
- Tag current stable state on main (example: `v1-stable-pre-migration`).
- Add `arch_version` to registry entries (`v1`, `v2_rope_swiglu`).
- Add `model_family` and `checkpoint_compat` fields.
- Add startup validation in runtime: refuse incompatible checkpoint/arch combos.
- Add migration utility script:
  - archive old `registry.json`
  - move old weights to `weights/archive/v1/`

### Exit Criteria
- Runtime rejects incompatible model loads with clear error message.
- `main` remains untouched and runnable as v1.
- `v2-modernization` runs only v2 schema/checkpoints.

### Rollback
- Roll back by switching branch/tag back to `main` / `v1-stable-pre-migration`.

---

## Phase 1 — Core DNA Mutation (2–3 days)

### Goal
Implement modern transformer core while preserving `bud()` and `_inherit_weights()` semantics.

### Scope
- `fractal_transformer.py`
  - RMSNorm
  - RoPE in attention
  - SwiGLU FFN
  - bias-free attention/FFN linears
  - updated `scale_config` with SwiGLU diet
- `weight_slicer.py`
  - slicing for `w1/w2/w3` and bias-free modules
- Distillation + forward loss paths
  - enforce `ignore_index=pad_id`

### Hard Constraints
- `head_dim % 2 == 0` assertion for RoPE safety.
- `bud()` must still return smaller child in train mode.
- Parent params unchanged after budding.

### Exit Criteria
- Unit-shape tests pass for parent and child models.
- Distillation loop runs on dummy batch without NaNs.
- Child checkpoint can be loaded by runtime using registry config.

### Rollback
- Use git branch rollback (no dual v1/v2 runtime code in same module).

---

## Phase 2 — Pretraining Stability Pass (1–2 days)

### Goal
Re-train v2 mother safely on M1/M2 with thermal-aware defaults.

### Scope
- `pretrain_mother.py`
  - `SEQ_LEN=256`
  - streaming + causal shift preserved
  - `optimizer.zero_grad(set_to_none=True)`
  - CE with `ignore_index=pad_id`
  - periodic MPS cache clear + gc
- Add explicit run banner warning:
  - "Clear/rotate registry for fresh architecture runs"

### Exit Criteria
- 500-step smoke run completes without OOM.
- 2,000+ step run stable with monotonic-ish loss trend.
- `weights/root_node_v2.pt` + v2 registry entry created.

### Rollback
- revert to prior checkpoint and v1 registry snapshot.

---

## Phase 3 — Conversational SFT Engine (2 days)

### Goal
Teach dialogue behavior without harming base reasoning.

### Scope
- New file: `src/training/train_sft.py`
- Dataset: `HuggingFaceH4/ultrachat_200k` (streaming)
- Format:
  - `<|user|>\n...\n<|assistant|>\n...<|endoftext|>`
- Tokenizer expansion:
  - safely add missing speaker tokens
  - resize token embedding + lm head
- Training:
  - LR = 2e-5
  - steps = 2,000
  - batch = 4
  - gradient clipping = 1.0
  - optional grad accumulation for MPS stability
  - CE `ignore_index=pad_id`

### Exit Criteria
- Fine-tuned checkpoint `weights/root_node_v2_sft.pt` saved.
- Chat coherence materially improved on held-out prompts.
- No catastrophic regression on general prompts.

### Rollback
- keep both pre-SFT and post-SFT checkpoints side-by-side.

---

## Phase 4 — Controlled Mitosis Validation (1 day)

### Goal
Prove domain specialization pipeline with deterministic finance child spawn.

### Scope
- `supervisor.py` test harness:
  - finance/audit-heavy mock corpus
  - low `min_history_len` for quick trigger
  - deterministic child ID: `finance_child_1`
- Ensure post-spawn actions are explicit and logged:
  - checkpoint write
  - registry entry write
  - router centroid update

### Exit Criteria
- `finance_child_1` appears in registry with complete config.
- Router can route finance query to child above threshold.
- Child can be loaded by runtime and generate response.

### Rollback
- prune test child via lifecycle manager.

---

## Phase 5 — Runtime Hardening & Serving Quality (2–3 days)

### Goal
Make inference robust under real chat workloads.

### Scope
- Add model cache policy in swapper (LRU/TTL).
- Add warm-start centroid hydration from registry.
- Add request-time safety:
  - max token cap
  - timeout handling
  - clean fallback to `root_node`
- Add generation policy presets:
  - creative / balanced / strict factual

### Exit Criteria
- Stable multi-turn chat for 30+ minutes on M1.
- No memory creep over repeated requests.
- Clear logs for routed node and confidence.

### Rollback
- disable advanced cache and use root-only fallback mode.

---

## Phase 6 — Evaluation, Benchmarking, and Release (2 days)

### Goal
Quantify gains and ship confidently.

### Evaluation buckets
1. **Language quality**: fluency, coherence, instruction-following.
2. **Routing quality**: expert hit-rate, confidence calibration.
3. **Efficiency**: latency, VRAM footprint, thermal behavior.
4. **Safety/robustness**: malformed prompt handling, fallback correctness.

### Release gates
- No blocker bugs in 48h soak run.
- Training and inference docs updated.
- Repro command list verified end-to-end.

---

## Metrics That Define "World-Class Progress"

Use measurable targets instead of vague claims.

### Model quality
- >=20% reduction in perplexity on internal validation slice vs v1.
- >=30% improvement in instruction adherence score (human rubric).

### System quality
- p95 inference latency under 1.8s at target max_len on M1.
- <5% routing misfires on curated domain test set.
- zero OOM events in 10k request simulation.

### Evolution quality
- successful deterministic spawn + load + route for finance expert.
- no registry corruption after 100 maintenance cycles.

## Practical Upgrade Order (Exact Execution)

1. Implement Phase 0 safety rails.
2. Implement Phase 1 architecture changes.
3. Run Phase 2 pretraining smoke (500 steps), then full run.
4. Implement and run Phase 3 SFT.
5. Execute Phase 4 deterministic finance mitosis test.
6. Finish Phase 5 runtime hardening.
7. Run Phase 6 evaluation gates and release.

Do not skip order. This sequence minimizes breakage risk.

### Phase-by-Phase Definition of Done

- **Phase 0 DoD**: incompatible checkpoint rejection works and stable v1 tag exists.
- **Phase 1 DoD**: model self-test runs; child budding still produces smaller, loadable checkpoints.
- **Phase 2 DoD**: 500-step smoke passes without OOM; full run produces stable loss trend.
- **Phase 3 DoD**: SFT checkpoint trains and chat responses improve stylistically.
- **Phase 4 DoD**: `finance_child_1` exists in registry, routes, loads, and generates.
- **Phase 5 DoD**: 30+ minute chat soak without memory creep or route failures.
- **Phase 6 DoD**: all gates green; documentation and commands are reproducible.

### Branch and Merge Discipline (Hard Cutover)

1. `main`: remains stable v1 until v2 gates are complete.
2. `v2-modernization`: all v2 work lands here.
3. Merge to `main` only after Phase 0–6 DoD checks pass.
4. Keep rollback tag (`v1-stable-pre-migration`) until first stable v2 release.

---

## Anti-Patterns to Avoid

- Mixing v1 and v2 checkpoints in one registry namespace.
- Deriving missing config fields at inference time.
- Ignoring padding tokens in only one training script.
- Launching SFT before v2 base pretraining stabilizes.
- Optimizing for benchmark numbers before runtime reliability.

---

## "No-Break" Operational Checklist

Before each merge to main:
- [ ] Registry schema validated.
- [ ] Backward compatibility decision documented (supported or intentionally dropped).
- [ ] Shape tests pass for parent + child load paths.
- [ ] One full inference round-trip test passes.
- [ ] MPS memory behavior checked on 30-minute run.
- [ ] Rollback command tested.
